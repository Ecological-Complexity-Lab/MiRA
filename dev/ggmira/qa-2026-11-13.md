Reviewed: ggmira `84cfb66`, bundling MiRA `354fc85`. Three independent
reviewers (Fable, high effort), each given the code and no conclusions:
**R** (the R package), **JS** (MiRA's R-facing JavaScript and the R ↔ MiRA
contract), **D** (documentation). IDs below keep each reviewer's numbering.

Baseline: ggmira tests pass (554); `R CMD check` 0 errors, 0 warnings, 1 note
(Rd image sizes); MiRA `npm test` 445/445; the R-related browser specs 48/48.
`inst/MiRA` is identical to MiRA `354fc85`.

"Confirmed" = the reviewer ran it. Six were re-run by the main session and
reproduce: JS1, D-W3, R-B19, R-B7 (`directed = "yes"`), R-B11 (palette
alone), D-W5.

Triage (proposed, not yet approved by Shai): **1** = fix before the release,
**2** = documentation only, **3** = after the release.

## Tier 2: documentation only

Wrong:
- D-W4: `bipartite` help omits the `type` column (what emln networks have), and nothing explains that it reaches MiRA as `node_type`.
- D-W6: `print()` / `plot_mira()` return `invisible(NULL)` when R is not interactive (documented: the server handle); `browser =` forces opening.
- D-W7: two expansions of "MiRA" in `?plot_mira`.
- D-W9: `browser = "firefox"` probably does not work on macOS (read only).

Missing:
- D-M1: computed node attributes are never defined (`intra|inter` × `in_|out_` × `degree|strength` × `_sum|_mean`; directed vs undirected names).
- D-M2: columns MiRA does not offer (`latitude`, `longitude`, `weight`, ids, …).
- D-M3: `mira_save()` limits (sizes, `resolution = 3`, `"jpeg"`, no transparent background in meta and dashboard, data view not saved, overwrite, the folder must exist).
- D-M4: MiRA's "Some plot settings from R were ignored" notice.
- D-M5: `plot_mira()` is not exactly MiRA's default view (legends minimized, map fitted).
- D-M7: `layer_name` / `.set` restrictions on `color_palette`, `color_reverse`, `color_limits`.
- D-M8: transparent colors, `pairs` without links, a bad `ggmira.viewer`, `nested` on a non-bipartite layout, the messages printed on every print, what `mira_spec()` shows.
- D-M9: usage lines show internal constants (`LEGEND_ALL`, `NETWORK_MODE`, `VIEWER_OPTION`).
- D-M10: `mira_spec()` is not in the article; `?mira` Components omits `mira_mode_*()`; no `mira_legends()` row in the `mira_mode` table; missing slider defaults (node size 10, label sizes 12 and 14).
- From R (design): bipartite networks from `emln::create_multilayer_network()` have no `node_type`; the error does not say how to add it. `directed = TRUE, directed_interlayer = FALSE` is silently ignored. Per-set values replace each other whole.
- From JS (design): the default layout of a unipartite network is random and unseeded (`mira(net)` differs between runs; no note); legends start minimized only in network mode; `mira_layer(color = )` does not color the layer-view bubbles.

Inconsistent:
- D-I1: where `mira_filter()` applies (article `:264`, `inst/examples/mira_examples.R:85`, `R/ggmira-package.R:42`, `R/mira.R:22` are stale: the layer view applies `layers`).
- D-I2: per-set arguments listed in `?mira_node` (palette, reverse, limits missing from the "Per set" paragraph).
- D-I3: which scale arguments exist (`?mira_scales` intro, `?mira`, the article name only two of five).
- D-I4: the default-scale rule (`?mira_scales` vs `?mira_options`; the code follows the second).
- D-I5: the article describes a "sets" column the printed output does not show.
- D-I6: `inst/examples/mira_examples.R` claims every argument; ten are unused.
- D-I7: "mode" vs "view" wording.
- D-I8: `docs/` (gitignored local build) is stale.

Minor / release prep: the Rd image-size NOTE (`width="100\%"` at `R/mira_mode.R:73,115,152,181,203,229`); `url: ~` in `_pkgdown.yml`; no `NEWS.md`; the repo is private (install command, README link and `mira_feedback()` fail for outsiders); README link to the `.Rmd`; "seven visualization models of MIRA"; pre-release text in `beta-testing.Rmd:23` and `inst/examples/mira_examples.R`; empty alt text on 19 of 20 article images; `testthat (>= 3.0.0)` but tests need 3.2.0; `stats` not in Imports.

## Tier 3: after the release (proposed)

- R-B8: the converter writes invalid JSON for `Inf` and control characters, and recurses on list columns (inherited from emln; the tests require byte-identical output).
- R (design): `net %>% mira()` records `mira(., …)` for the R button; `mira()` takes 7.3 s on 30,000 links; components cannot be combined before a plot; `pairs` cannot be cleared; RStudio Server / Posit Cloud (inferred); one headless Chrome stays alive after `mira_save()`; `mira_feedback()` URL length.
- JS nitpicks: the Cmd+drag note tests the wrong shape (`js/rCode.js:349`, and `tests/rCode.test.js:252`); attribute names containing `:`; `set_labels = FALSE` on a non-bipartite plot; an attribute named `constructor`; a network variable named `p` with the Viewer code; empty-string values; the keydown listener; a stale comment (`js/rBridge.js:82`); `mira_camera()` changes the renderer's zoom in map mode.
- R nitpicks: palette-index colors (`"1"`), `"#fff"`, `mira_spec(json = "yes")`, `highlight = 100000`.

## Clean

Filters from R; component order; `viewer` / `browser` / `ggmira.viewer` precedence; path traversal (macOS); server cleanup after `mira_save()`; `mira_save()` at ordinary sizes in every view (emln 17, 23); camera round trip; `screenSize.js`, `cameraReadout.js`, `sessionManager.js`; all documented ranges and palette lists; `man/` in sync with roxygen; every documented call matches the current signatures.
